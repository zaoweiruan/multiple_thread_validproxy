## 3. 异常诊断

### 🔴 关键发现

1. **存活状态全部为"否"**：3个代理均标记为未存活，但状态仍显示 `active`，存在状态不一致
2. **延迟均为 -1**：通常表示未检测到有效延迟或代理不可达
3. **失败次数为 0**：结合存活=否，可能刚初始化尚未完成健康检查，或检查逻辑存在异常

### 可能根因

- **健康检查未执行**：虽然"上报健康"已勾选，但可能未触发或后台检查线程异常
- **存活判定逻辑缺陷**：`active` 状态与 `存活` 字段未联动更新
- **代理刚加入池未检测**：成员刚添加，延迟测试尚未完成（-1 为默认值）
- **自动删除未开启**：由于"自动删除死亡"未勾选，死亡代理未被清理，导致池内存在无效成员

---

## 4. 修复建议

### 4.1 立即操作（用户侧）

1. **点击"刷新"**：手动触发一次健康检查，观察延迟和存活状态是否更新
2. **勾选"自动删除死亡"**：避免无效代理长期滞留池内
3. **勾选"自动优化"**（可选）：启用自动剔除低质量代理

### 4.2 代码层修复（开发侧）

| 优先级 | 修复点 | 说明 |
|--------|--------|------|
| P0 | **存活状态同步** | 当代理检测为死亡时，状态应从 `active` 更新为 `inactive` 或 `dead` |
| P1 | **延迟默认值处理** | -1 应明确表示"未检测"，而非有效延迟，UI 上可显示为 `--` 或 `N/A` |
| P2 | **健康检查触发** | 确认代理加入池后是否自动启动健康检查线程 |
| P3 | **状态一致性校验** | 增加状态机约束：`存活=否` 时禁止显示 `active` |

---

## 6. 结论

当前代理池处于 **"伪活跃"** 状态：3个代理均显示为 `active` 但实际未存活。建议**立即刷新检查**，若延迟和存活状态无变化，需排查健康检查线程及状态同步逻辑。短期可通过开启"自动删除死亡"缓解，长期需修复存活判定与状态同步的代码缺陷。
