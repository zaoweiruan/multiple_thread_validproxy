## 二、优化建议中值得保留的内容

以下六项，我建议全部保留。

### 1\. 分层记忆架构

这是本次优化最有价值的部分。

建议采用：

第一层 · 常驻

AGENTS.md

保存稳定项目约束、长期偏好、安全红线、工具优先级和验证门禁。

第二层 · 按需加载

docs/ 专题文档

保存技术方案、CLI 手册、模块映射、调试方法、历史故障和详细工具说明。

第三层 · 动态记忆

项目跟踪器及 Caura

项目跟踪器管理进度；Caura 保存已确认的架构决策、历史经验和长期偏好。

这样可以避免每次处理一个小问题，都必须加载完整的项目知识。

### 2\. 删除机械式关键词触发

原文件 §6.2 的问题比较明显：

- 用户一句话可能命中多个关键词。
    
- 引用某个关键词也可能触发不必要的技能。
    
- 技能不存在时没有明确降级方式。
    
- 一个简单问题可能被强制要求执行完整研发流程。
    

建议保留意图路由，但增加：

- 根据实际任务判断是否需要技能。
    
- 先检查技能是否存在。
    
- 工具不可用时使用可行的替代方案。
    
- 不允许虚构工具执行结果。
    

这一修改值得保留。

### 3\. CLion MCP 优先原则

原文件 §6.3.5 是重要的长期开发约束。

建议保留：

- 符号定位优先使用 CLion MCP。
    
- 静态诊断优先使用 `get_file_problems`。
    
- 复杂行为问题优先采用断点调试。
    
- 数据库核验优先使用数据库连接和 SQL。
    
- 所有工具显式指定 `projectPath`。
    
- 中文修改避免使用存在字符丢失风险的 `apply_patch`。
    
- CLion 不得替代 CTest、UI 自动化、ASAN 等正式验收。
    

尤其不能因为精简 AGENTS.md 而丢掉这些规则。

### 4\. 工具能力检查和降级机制

这是优化草案新增的正确设计。

必须避免这样的情况：

AI 被要求调用某个 MCP 工具，但工具实际上不存在，最后却声称已经完成检查。

建议将以下原则作为常驻硬约束：

工具必须先确认可用，再调用；无法调用必须明确说明，不得伪造执行结果。

### 5\. 验证证据制度

优化草案要求完成声明提供：

- 实际执行命令。
    
- 退出码。
    
- 测试通过、失败和跳过数量。
    
- 未执行的验证项目。
    
- 尚存风险。
    

我建议完整保留。

这对于 C++ 多线程、SQLite、Xray 进程管理等模块尤其重要。

### 6\. 角色分工简化

原文件六个角色的职责细则与前面的研发流程存在重复。

建议保留角色简表，但让角色负责不同职责，而不是每个角色都重新定义一套流程。

简单任务不必强制经过六个角色。

## 三、必须修正的五个问题

这部分是我认为不能直接采用优化草案的主要原因。

### 1\. C++ 标准存在错误建议

必须修正

优化建议第一部分写道：

> 常驻规则统一写为 C++20。

但原始文件明确写的是 C++20/17，括号中指定标准为 C++17，而且多处明确要求 C++17。

优化草案本身也写回了 C++17。

最终决定：统一为 C++17，不升级到 C++20。

没有用户明确的升级决定，不得改变项目语言标准。

### 2\. 构建产物路径不能简单统一

必须核验

原文件存在两个不同的路径概念：

- `build/`：CMake/Ninja 构建目录。
    
- `bin/`：项目约定的运行产物目录。
    

同时明确禁止使用 `bin/worker/validproxy.exe` 进行问题复现。

不能把构建目录和最终运行产物目录混为一谈。

最终规则应该是：

1.  使用 `build/` 执行构建。
    
2.  根据实际 CMake 配置确认构建产物。
    
3.  使用本次构建的最新产物验证。
    
4.  严禁使用 `bin/worker/` 中的陈旧副本。
    

### 3\. PowerShell 命令兼容性

优化草案使用了：

```
cmake --build build --parallel 8 && ctest -V
```

`&&` 在 PowerShell 7 中可用，但 Windows PowerShell 5.1 不支持。

既然项目没有明确限定 PowerShell 7，最终常驻文档应采用逐条执行的形式，并检查退出码。

### 4\. 数据库路径仍有歧义

原文件存在：

- `test/guindb.db`
    
- `test/guiNDB.db`
    
- `test/guiNDB_empty.db`
    
- `bin/test_config.json`
    

这些名称不能凭文件名推断其关系。

优化草案正确地提出了待核验，但最终版本还应明确禁止未经核验就修改、合并或重命名数据库。

### 5\. 不能丢失 UI 和代码评审规则

优化草案简化角色定义是正确的，但部分细节不应该丢失：

- UIA 与 Win32 窗口定位。
    
- `tests/ui/UIIds.h` 控件定位规范。
    
- UI 自动化验收要求。
    
- 多线程竞态、UAF、双重释放等代码审查重点。
    
- reviewer 独立评审原则。
    
- UI 自动化与 CLion 调试器的边界。
    

这些内容已经在最终版本中保留为精简的执行约束，详细工具参数和模型选择则应该放入专题文档。

## 六、最终结论

最终推荐：采用修订版

我不建议继续维护原来 325 行的 AGENTS.md，也不建议直接照搬原优化草案。

- AGENTS.md 负责约束 AI 的行为。
